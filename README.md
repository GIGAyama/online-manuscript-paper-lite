# **オンライン原稿用紙 Lite 📝**

**サーバー不要、アカウント不要、配布するだけ。**

GIGAスクール構想下の教育現場のために設計された、ブラウザだけで動作する軽量な縦書き原稿用紙アプリです。

先生向けの操作手引きは **[MANUAL.md](MANUAL.md)** にあります。
実測値と監査の記録は [AUDIT.md](AUDIT.md)、改修の経緯は [ROLLOUT.md](ROLLOUT.md) にあります。

## **🌟 概要**

「オンライン原稿用紙 Lite」は、Google Apps Script (GAS) やデータベース、
ログインの仕組みを一切使用しない、クライアントサイド完結型のWebアプリケーションです。

左の入力欄に打つと、右の原稿用紙に縦書きで即座に反映されます。
そのまま A4横・二段組の原稿用紙として印刷（PDF保存）できます。

### **なぜ Lite なのか？**

* **導入が圧倒的に簡単**: 一式を Web サーバーに置くか、児童・生徒の端末に配るだけ。サーバー側の設定はありません。
* **プライバシー**: 入力されたデータはサーバーに送信されず、すべて端末内（ブラウザの `localStorage` とローカルファイル）で完結します。
* **メンテナンスフリー**: データベースの管理やAPIの制限、利用者アカウントの管理が要りません。

## **✨ できること**

### **1. 縦書きリアルタイムプレビュー**

* 左の入力欄に打つと、右の原稿用紙に即座に縦書きで反映されます。
* **題名**は自動で先頭から2マス下げて置かれます。
* **学年・組と名前**は題名の次の行に、行末から1マス空けて置かれます。
* 原稿用紙は常に1ページ分（20行 or 16行）の倍数で描かれるので、途中でも用紙の形が崩れません。
* プレビューは表示領域の高さに合わせて自動で拡大・縮小されます（最大3倍）。
* 入力欄と原稿用紙の**スクロールは連動**します。どちらを動かしても、もう一方が同じ位置へ追従します。

### **2. 禁則処理（自動）**

| 種類 | 動き |
|---|---|
| **行頭禁則** | `、` `。` `」` `』` `）` `っ` `ゃ` `ー` `？` `！` `々` などが行の頭に来ないようにします |
| **行末禁則** | `「` `『` `（` `【` などの開き括弧が行の最後のマスに来ないよう、先に次の行へ送ります |
| **文字の圧縮** | `。」` `、」` `！」` `？」` などの組み合わせを**1マスにまとめて**入れます |

行頭禁則の解決の仕方は、設定で2つから選べます（既定は**ぶら下がり**）。

* **ぶら下がり** … マスの外へ小さく出します。はみ出しすぎないよう**2マス分まで**に留め、それ以上は次の行の頭へ置きます。
* **追い出し** … 前の行の最後の1字を次の行の頭へ送ります。

### **3. 用紙・禁則処理の切り替え**

画面右上の**歯車（⚙）**を押すと設定が開きます。

| 設定 | 選べるもの | 既定 |
|---|---|---|
| 用紙の文字数 | **20字 × 20行**（高学年）／ **15字 × 16行**（低学年） | 20字 × 20行 |
| 禁則処理 | **ぶら下がり** ／ **追い出し** | ぶら下がり |

選んだ内容は作文と一緒に保存され、次に開いたときも同じ設定で始まります。

### **4. 保存と読み込み**

| ボタン | すること |
|---|---|
| **新規** | 題名・学年・氏名・本文を消してまっさらにします（確認ダイアログが出ます） |
| **開く** | 書き出した `.txt` を読み込みます |
| **保存する** | 作文を `.txt` にして端末へ書き出します |

* **自動保存**: 入力が止まってから**約1秒後**にブラウザへ保存されます（`localStorage['genko_lite_v2']`）。
  さらに画面を離れる合図（`pagehide`）でも確定させるので、Chromebook がメモリ不足でタブを破棄しても直前の数文字が残ります。
  次に開くと自動で復元され、中身があれば「前回の続きから始めます」と表示されます。
* **ファイル保存**: 下記の形式のテキストファイル（UTF-8）を作ります。
  ファイル名は `題名_氏名.txt`。題名も氏名も空（または記号だけ）のときは `作文_YYYY-MM-DD.txt` になります。
  題名も本文も空のときは「まだ何も書いていません」と出て保存しません。
* **読み込み**: `.txt` を選ぶと、下記の見出しを手がかりに題名・学年・氏名・本文へ振り分けます。
  見出しが見つからないファイルは、確認したうえで**全文を本文として**読み込みます。
  Windows のメモ帳などで保存し直して改行が CRLF になっていても正しく読めます。

書き出される `.txt` の中身：

```text
【題名】ぼくの夏休み
【学年】5年2組
【氏名】山田太郎
---------------------------
（ここから本文）
```

### **5. 印刷・PDF化**

* 「印刷する」ボタン、またはブラウザの印刷機能（Ctrl + P）で印刷できます。
* レイアウトは **A4横・二段組**に固定です。中央に魚尾（とじしろ）があり、
  そこに**題名の先頭10文字**と**ページ番号**が入ります（題名が空のときは「無題」）。
* 本文が長ければ自動で複数ページに分かれます。
* 印刷設定で **A4／横／倍率100%／背景のグラフィック オン** にしてください。
  背景のグラフィックが切れていると原稿用紙のマス目が印刷されません。

### **6. PWA対応（アプリとしてインストール可能）**

* ChromeやEdgeのアドレスバーに表示されるインストールアイコン、または画面右上の「インストール」ボタンから、アプリとして端末にインストールできます。
  （このボタンはブラウザがインストール可能と判断したときだけ出ます。iPad・iPhone の Safari には出ないため、共有ボタンの「ホーム画面に追加」を使います。手順は [MANUAL.md](MANUAL.md) にあります。）
* 一度読み込めば、オフラインでも起動・編集ができます（Service Workerによるキャッシュ）。
* 新しい版が届くと、画面下に「あたらしい ばんが あります」と出ます。
  **押すまで切り替わりません**（打ちかけの作文が消えないようにするため）。
* ※インストールとオフライン機能は、HTTPSで公開した場合（GitHub Pagesなど）に有効です。ファイルを直接開く方法（`file://`）でも通常のWebページとしては問題なく動作します。

### **7. 児童・生徒が使うための配慮**

* **ふりがな（ルビ）**が画面の見出しやボタンに付いています。
* **文字数**が入力欄の右下に出ます。**改行は数えません**（原稿用紙の400字と見比べるため）。絵文字や一部の漢字も1文字と数えます。
* 画面幅が狭い端末（およそ768px未満）では「かく」と「原稿用紙をみる」を**タブで切り替え**て、どちらも画面いっぱいに大きく表示されます。
* ソフトキーボードが出ても入力欄が隠れないよう、実際に見えている高さに追従します。
* タップ領域は44px以上、コントラストは基準を満たし、キーボードだけでも操作できます（詳細は [AUDIT.md](AUDIT.md)）。
* 拡大（Ctrl + ホイール、2本指で広げる）は妨げていません。

## **🚫 できないこと（はっきり書きます）**

* **クラウド保存・提出機能はありません。** Google ドライブや OneDrive の API とは連携しません。
* **端末をまたいだ同期はありません。** 別の端末・別のブラウザ・シークレットウィンドウでは前の内容は出ません。
* **先生が児童の作文を集めて見る仕組みはありません。** サーバーが無いので、書いたものは端末の中にしかありません。
* **原稿用紙は 20字×20行 と 15字×16行 の2種類だけ**です。任意のマス目にはできません。
* **印刷は A4横・二段組に固定**です。縦向きや一段組にはできません。
* **本文にふりがな・太字・色などの書式は付けられません。** 扱えるのはプレーンテキストだけです。
* **画像や表は入れられません。**
* **複数の作文を同時に持てません。** 保存されるのは常に「いま書いているもの」1つだけです。別の作文は `.txt` に書き出して残してください。

## **🚀 導入方法（先生・管理者向け）**

以下のいずれかの方法で利用を開始できます。

### **方法A: GitHub Pages で公開する（推奨）**

1. このリポジトリを Fork するか、**リポジトリ一式**を自分のリポジトリに配置します。
2. GitHubリポジトリの Settings > Pages から、公開元（Source）を `main` ブランチに設定します。
3. 発行されたURLを児童・生徒に共有してください。

> `manifest.webmanifest` の `start_url` / `scope` / `id` は
> `/online-manuscript-paper-lite/` を指しています。
> 別のリポジトリ名で公開する場合は、この3か所と `quality.config.json` の `basePath` を
> 実際のパスに合わせて書き換えてください（書き換えないとインストールが働きません）。

### **方法B: ファイルとして配布する**

1. リポジトリ一式（`index.html` / `css/` / `js/` / `vendor/` / `icons/` / `manifest.webmanifest` / `install-hook.js` / `sw.js` / `offline.html` / `favicon.png`）をダウンロードします。
2. Google ClassroomやMicrosoft Teams、USBメモリなどを通じて、児童・生徒の端末に配布します。
3. `index.html` をダブルクリックしてブラウザ（ChromeやEdge）で開くだけで使えます。

> **`index.html` 1ファイルだけでは動きません。** 実行コードを CDN から取るのをやめ、
> すべて自分側（`vendor/` `js/` `css/`）に置いたためです。理由は「ビルドと依存」の節にあります。
> なお `file://` で開いた場合、アプリとしてのインストールとオフライン機能は働きません
> （ブラウザの仕様）。書く・保存する・印刷するはできます。

### **動作環境**

* Chrome / Edge / Safari の、おおむね2022年以降の版（ビルドの対象は Chrome 100・Safari 15 以降）。
* JavaScript が有効であること（無効だとその旨のメッセージが出ます）。
* インストールとオフライン機能には HTTPS が必要です。

## **📖 使い方（児童・生徒向け）**

1. **書く**: 「だいめい」「がくねん・くみ」「なまえ」を入力し、大きな枠に本文を書きます。
2. **保存する**:
   * 自動でブラウザに保存されます（打ち終えて約1秒後）。
   * 「保存する」ボタンを押すと、パソコンの中にファイル（`.txt`）として保存できます。提出用に使えます。
3. **続きから書く**:
   * 同じパソコンの同じブラウザなら、また開くだけで続きから書けます。
   * 「開く」ボタンから、保存したファイルを選んで読み込むこともできます。
4. **やりなおす**: 「新規」ボタンで、いま書いているものを消してまっさらにできます（確認が出ます）。
5. **印刷する**: 「印刷する」ボタンを押して、プリンターを選んで印刷するか、PDFとして保存します。

## **🛠️ 技術スタック**

* **HTML5 / CSS3 / JavaScript (ES6+)**
* **React 18** … UIライブラリ。`vendor/` に自己ホスト（UMD 版をページ側の `<script>` で読む）
* **Tailwind CSS 3** … スタイル。**ビルド時に**使うクラスだけの CSS を作る
* **SweetAlert2** … 確認ダイアログとトースト。`vendor/` に自己ホスト
* **esbuild** … JSX の変換と最小化（ビルド時のみ）
* **アイコン** … bootstrap-icons から必要な13個だけを SVG として同梱（フォントは配らない）
* **Google Fonts** … Zen丸ゴシック（UI用）、Zenオールド明朝（原稿用紙用）。
  ここだけは CDN のまま。届かなくても端末側の日本語フォントに落ちるだけで、動作には影響しない
* **PWA** … Web App Manifest + Service Worker によるインストール・オフライン対応
* **ビルド以外の依存はゼロ**。実行時にフレームワークやパッケージマネージャは要らない

## **🧱 構成 ── 原本と生成物**

**原本（ここを直す）**

| ファイル | 中身 |
|---|---|
| `src/app.jsx` | 画面。React コンポーネントと状態 |
| `src/genko-parser.js` | 原稿用紙の組版（禁則処理）。画面に依らない純粋な計算 |
| `src/style.css` | Tailwind の指示 + 追加スタイル（印刷・セーフエリア・ふりがな等） |
| `tailwind.config.js` | 配色とフォントの並び |
| `tools/build.mjs` | ビルド |
| `tools/make-icons.mjs` | アイコン画像（`icons/` `favicon.png`）の生成。`sharp` が要る |
| `tools/measure/` | 実ブラウザでの計測。`playwright-core` が要る |
| `scripts/check-project.mjs` `scripts/lib/` | 品質ゲート（`npm run check`） |
| `tests/` | 組版ロジックのテストと、品質ゲート自体の自己テスト |
| `quality.config.json` | 品質ゲートのしきい値（初回JSの上限・画像の上限・版番号など） |
| `index.html` `sw.js` `install-hook.js` `offline.html` `manifest.webmanifest` | そのまま配られる |

**生成物（手で編集しない）**

`js/app.js` / `js/icons.js` / `css/style.css` / `vendor/react.js` / `vendor/react-dom.js` / `vendor/sweetalert2.js`
（および `npm run icons` を走らせたときの `icons/*.png` と `favicon.png`）

> **原本を直したら、必ず `npm run build` を走らせてから push すること。**
> GitHub Pages はリポジトリの中身をそのまま配るので、生成物もコミットしてある。
> ビルドし忘れた PR は CI（`git diff --exit-code -- js css vendor`）で落ちる。

```bash
npm ci
npm run build      # 生成物を作り直す
npm run check      # 品質ゲート（CI と同じもの）
npm test           # 組版ロジックと、ゲート自体の自己テスト
```

アイコンを作り直すとき（`sharp` が要る）:

```bash
npm i --no-save sharp && npm run icons
```

実ブラウザで測るとき（`playwright-core` が要る）:

```bash
npm i --no-save playwright-core && npm run measure
```

Service Worker を更新したときは、`sw.js` の `APP_VERSION` と
`quality.config.json` の `appVersion` を**両方**上げること（食い違うと品質ゲートが落ちる）。

## **📦 ビルドと依存（なぜビルドがあるか）**

以前は `cdn.tailwindcss.com` / `unpkg.com` / `cdn.jsdelivr.net` から
React・Babel・Tailwind・SweetAlert2・アイコンフォントを読み、
**ブラウザの中で JSX をコンパイル**していました。

学校のネットワークはこれらの CDN を塞いでいることがあります。
**1本でも届かないと画面が真っ白になり、原因がアプリの外にあるので先生が調べても分かりません。**
また `@babel/standalone` だけで約 3.1MB あり、開くたびに全部コンパイルし直していました。

いまは実行コードをすべて自分側に置き、JSX はビルド時に1回だけ変換しています。

| | 前 | 後 |
|---|---:|---:|
| 初回に必要な JS | **3,284 KB** | **254 KB** |
| CDN から取る実行コード | 5本 | **0 バイト** |

内訳（後）: `react-dom.js` 128.7KB ／ `sweetalert2.js` 77.3KB ／ `js/app.js` 30.3KB ／
`react.js` 10.5KB ／ `js/icons.js` 6.4KB ／ `install-hook.js` 1.0KB。
初回JSの上限 300KB は `quality.config.json` に書いてあり、ビルドと品質ゲートの両方で見ています。

## **🔒 セキュリティ設計**

* サーバーを持たないため、送信も認証もありません。入力は**その端末の中だけ**に残ります
  （`localStorage['genko_lite_v2']`）。
* CSP（Content Security Policy）を `index.html` に入れてあります。
  実行コードは `'self'`（と `file:`）のみ。`script-src` に `'unsafe-inline'` は**付けていません**。
  そのためインラインの `<script>` と `onclick=` は使えません（使うと動きません）。
  `style-src` の `'unsafe-inline'` は、React と SweetAlert2 が `style` 属性を書くため外せません。
* `frame-ancestors` は `<meta>` では無視されるため書いていません。
  他サイトへの埋め込みを止めるには HTTP ヘッダーが必要で、GitHub Pages では足せません。
  独自ドメインや CDN を前に置く場合は、そちらで設定してください。
* Service Worker は**自分の接頭辞（`genko-lite-`）のキャッシュだけ**を消します。
  旧配信元の `gigayama.github.io` は多数のアプリが同じオリジンを共有していた。同居する配置に戻したときのため、
  全部消すと他のアプリがオフラインで起動しなくなります。
  同じ理由で `localStorage.clear()` も使いません。
* Service Worker は画面遷移を network-first、その他の同一オリジンの静的ファイルを cache-first で扱います。
  **200 以外の応答はキャッシュしません**（フィルタリングのブロック画面を控えにしてしまわないため）。

## **📐 制限**

* 1つの端末・1つのブラウザの中で完結します。端末をまたいだ同期はありません。
* iOS Safari は、7日間開かないと保存内容を消すことがあります（ITP）。
  ホーム画面への追加を推奨し、大事な作文はファイルへ書き出してください。
* 保存されるのは常に1つの作文だけです（新しく書くと前の内容は上書きされます）。
* 印刷は A4 横・二段組に固定です。
* 用紙は 20字×20行 と 15字×16行 の2種類だけです。

## **⚠️ 外部サービスとの連携について**

このアプリは、GoogleドライブなどのクラウドストレージAPIとは直接連携しません（Lite版の設計思想のため）。

クラウドに保存したい場合は、以下の手順で行ってください。

1. 「保存する」ボタンで端末に `.txt` ファイルをダウンロード。
2. そのファイルを Googleドライブ や OneDrive、Google Classroom などに手動でアップロード。
